# Mermaid scrollbar bug
_Exported on 9/21/2026 at 13:49:42 PDT from Cursor (3.21.16)_

---

**User**

The problem is that when the diagram on mermaid Tab properties are modified, a scrollbar appears temporarily—as shown in the attached screenshot. 
This is completely incorrect, as the space for the Mermaid diagram should be determined by the area allocated by its parent and must never expand beyond those boundaries. 
To achieve this, a technique is used where the parent has `position: relative` and the child has `position: absolute`; and `inner: 0;` this ensures the inner child has a explicilty  defined size that fits within the intended area.

Mermaid’s renderer is appending a temporary diagram to `document.body`, which briefly grows the page. I’ll render into a parent-sized `absolute inset-0` box instead so the pane never expands past its allocated area.

The page scrollbar flashed because a style change re-ran official `mermaid.render()`, which temporarily appended the full diagram to `document.body`. That extra height sat outside the preview pane, so the window scrolled for a moment and then snapped back.

The Mermaid pane now takes its size only from the parent (`relative` + `absolute inset-0`). The diagram is rendered into that box, not onto the page:

- The preview column is a `relative flex-1 min-h-0` parent with an `absolute inset-0 overflow-hidden` child, so the canvas has an explicit width and height.
- `mermaid.render()` writes into that same inset-0 host (hidden, clipped), so a re-render cannot grow the document.
- The visible Mermaid view is also clipped with the same pattern.

I verified this in the app: selecting a block, opening **Block style**, and changing color/dash updated the diagram with no document overflow and no stray mermaid nodes on `body`.
