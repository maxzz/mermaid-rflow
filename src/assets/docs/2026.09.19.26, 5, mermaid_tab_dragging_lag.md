# Mermaid tab dragging lag
_Exported on 9/19/2026 at 20:56:58 PDT from Cursor (3.21.16)_

---

**User**

When dragging a shape in the Mermaid tab, something strange happens: the shape lags behind the mouse cursor, resulting in a terrible user experience. 
There is no such issue when dragging a shape in the Flow tab; this problem exists only in the Mermaid tab.

---

**Cursor**

I'll investigate the Mermaid-tab drag path versus Flow, starting with the overlay and layout code that handle shape movement.

The overlay remasures every node on each pointer move, which would explain the lag. I'll compare that with Flow's drag path and the layout helpers next.

The lag is from remesuring every node and edge on each pointer move, which also tears down the overlay effect. I’ll drag the SVG directly and commit layout only on pointer-up, matching the Flow tab.

`applyMmdLayout` still resets every node and rewrites every edge on each move. I'll add a drag-only path that updates just the dragged shape and its connected edges.

The cursor mismatch is a scale bug: viewBox-to-rect mapping is non-uniform, so the shape moves slower than the pointer on X. I'll convert deltas through the SVG screen CTM instead.

Dragging in the Mermaid tab lagged because the pointer and the shape were not in the same coordinate space, and each move was doing far too much work.

**Why Flow felt fine:** React Flow moves the node with a transform on the pointer. Mermaid was writing layout state on every `pointermove`, which re-rendered the overlay and remesured every node and edge (including `getPointAtLength` along each path). The shape painted a frame or more behind the cursor.

**Why it also drifted:** pointer deltas were converted with `viewBox / getBoundingClientRect`. After the SVG size is pinned, those aspect ratios do not match, so the shape moved slower than the mouse on X (about 62% in the sample diagram). That reads as the node trailing the cursor.

**What changed:**
- During drag, only the dragged node and its edges are updated in the SVG; layout is committed on pointer-up.
- Overlay hit boxes are not remesured while dragging.
- Pointer deltas go through the SVG screen CTM, so movement stays 1:1 with the cursor, including when zoomed.

Verified in the Mermaid tab: a 140px diagonal drag tracked within 0.01px, and a zoomed drag within 0.02px. Edges and the selection outline stay with the node.
